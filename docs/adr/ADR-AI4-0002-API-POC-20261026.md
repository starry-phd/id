# ADR-AI4-0002｜Starry Phase 0 Hono / Zod / OpenAPI / SDK 選型 POC（候選）
- 日期：2026-10-26
- Owner：AI-4，決策權：AI-0
- 狀態：**proposed/candidate，非正式選型通過**。依據 PR #25 registry `API-001=candidate`。
- Starry-only。H-Global ID 完全獨立，此 Repo 不開發其實作。

## 可重現最小 POC
1. 已實作 native Fetch Worker `GET /v1/health`、OpenAPI 3.1 **只有此路由**（`apps/api/openapi.yaml`），`packages/sdk` 有 typed、無憑證、無跨品牌呼叫的 liveness client。
2. `apps/api/test/openapi-parity.test.mjs` 比對唯一 public path 與實際 Worker handler。SDK 單元測試檢查錯誤品牌、Production 壞輸入、無憑證以及 no-network disabled sync。
3. **未引入 `hono` / `zod` 套件**：本輪是 schema-first+typed SDK 的基礎 POC，不冒稱 Hono/Zod 運行或 codegen，亦不製造無權威 Auth/Billing/Member API。

## 方案比較／Gate 決策
| 方案 | 好處 | 風險 | 判定 |
| --- | --- | --- | --- |
| Native Fetch + OpenAPI 檔案 + 手寫 SDK | 零額外 runtime deps，最小攻擊面；Phase0 已可執行 | 文檔與 handler 可能漂移 | 現行 POC，parity test 強制 |
| Hono + Zod schema-first OpenAPI + generated TS SDK | 請求邊界驗證、重用 types，有生成流程潛力 | 額外套件、生成/運行 schema 仍需檢測，工具版本遷移 | **候選**，等 AI-0 Gate 契約決議再做 runnable dependency POC |
| 不驗證 request/response 的直接 JSON／any SDK | 省時 | 可偽造 Auth/Domain 狀態 | 拒絕 |

### 接入前驗收條件
- AI-1 明確擁有 Starry Auth/Profile 真實 DTO、可信 backend principal；AI-4 只做 transport、SDK、OpenAPI。
- `Hono`/`Zod`/OpenAPI adapters 決議後鎖版於 lockfile；正反 schema fixtures、TS 契約、worker runtime errors、HTTP method/route parity 完整測試。
- 無 H-Global 共用 Session/DB/Auth；跨品牌預設 DISABLED；禁止未簽署 token / 客戶端宣稱 admin 權限。
- 此 ADR 及 PR 須 AI-0 審核才能變更 `API-001` 的 candidate 狀態。
