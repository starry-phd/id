## Actual implemented source
- `src/m1-local-auth-session-core.ts`: `beginOAuthAttempt()` generates server-side cryptographic state, PKCE S256 verifier/challenge and nonce; persists one-time state locally and returns only public authorization parameters (not verifier). Callback uses existing pinned RS256 OIDC verifier and original atomic consumed-at CAS; failed code exchange/nonce/signature leaves state consumed and non-replayable.
- Constructor privately copies provider, issuer, client ID and JWKS; server-owned provider registry and keyring must not be supplied by client. Only `(provider, provider_subject)` forms identity lookup: **no email/display-name merging, no fallback to client user ID**.
- For returning member: verify existing active identity; for first verified subject: use random Starry `s_user_id` (no client-chosen ID), active member/default private directory flags and unique provider+subject identity.
- Both branches sign with existing non-extractable HMAC key port, check trusted clock again after awaited operations, then issue **one atomic trusted D1 batch transaction**: conditional current-member/current-subject Session INSERT plus an internal minimal audit-intent; new member also inserts Member, Identity and registration audit-intent in the **same transaction**. Unique member/provider/session/refresh and foreign keys enforce collision rollback. No bearer leaves the server until all statements report exactly one changed row. No `INSERT OR REPLACE`.
- Reuses existing W3 handler with its current HMAC/Session/Member/identity check and final self-profile SELECT; 200 response has exactly five fields, unchanged. Mutation/deletion/read-side PITR remain out of scope; audit-intent is not an external Queue/ACK.
- `schema/002_m1_local_oauth_attempts.DRAFT.sql`: local one-time attempts and durable minimal audit-intents with unique operation/event pairs. **Not a production migration.**

## Transaction assumptions and rollback
`authDb.batch()` must provide **real all-or-nothing authoritative SQLite/D1 transaction semantics**; do not inject an adapter which independently commits individual writes. For the first login, UNIQUE(provider,subject) contention aborts the loser and rolls back attempted orphan member, session and audit. Existing-account Session insert repeats active member/auth_version/provider-link checks at commit. Failure never returns a signed bearer; the consumed OAuth attempt is intentionally not undone. Minimal audit-intent resides in source DB transaction only, not a claim of remote durable Queue delivery.
